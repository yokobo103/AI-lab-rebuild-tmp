# CSS 落とし穴メモ

このプロジェクトで実際にハマったレイアウトの罠と、その回避方針を残す。新しく踏んだら追記する。

## 原則

- **位置ズレを `left` / `margin` / `transform` のオフセット値で殴らない。** 「あと数px右／左に…」と手で数字を足し引きしたくなったら、それは配置コンテキスト自体が歪んでいるサイン。オフセットではなく原因を直す。マジックナンバー（`-21px` など）はほぼ確実に別の環境幅で破綻する。
- **「合った」は目視でなく数値で確認する。** 各要素の `getBoundingClientRect()` の中央値を出し、ページ中央との差分を見る。一部要素だけズレていても即バレる。複数のブレークポイント（例: 1900 / 1280 / 375px）で測る。

## grid + justify-items:center で中央がズレる

**症状:** `display:grid; justify-items:center` のコンテナで、子要素がページ中央ではなく少し右（または左）に寄る。しかも要素ごとにズレ量が違うことがある。

**原因:** `grid-template-columns` を明示していないと、暗黙カラムは**一番幅の広い子に合わせて伸びる**。子がコンテナより広い（例: 大きな見出しがコンテナ幅を超える）と、カラムがはみ出す。グリッドカラムは既定で左寄せ配置なので、はみ出し分はすべて右へ流れ、`justify-items:center` の中央基準がカラム中央＝はみ出し子の中央にズレる。

**回避:**

- 中央寄せカラムには `grid-template-columns: minmax(0, 1fr)` を明示し、カラムをコンテナ幅に固定する。これで幅広の子もコンテナ中央基準で左右対称にはみ出す。
- あるいは単純な縦積み中央寄せなら `display:flex; flex-direction:column; align-items:center` を使う。`align-items:center` は幅超過の子も対称にはみ出させるので事故りにくい。

**実例（2026-07 修正）:** トップページ hero の `.hero-section__content-inner`。見出し `<h1>` がコンテナ(720px)より広い(788px)ため上記の罠にハマり、コピー全体が右へズレていた。`--hero-copy-offset-x: -21px` で一部要素だけ殴って余計にバラけていたのを、`grid-template-columns: minmax(0, 1fr)` で根治しオフセットを撤去した。
